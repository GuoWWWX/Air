## Air Proxy 1.1.5

- Windows 和 Android 的手动测速按点击时页面上的节点顺序开始。有节点完成就补下一个，已勾选的节点也按页面顺序测试。Windows 从当前页开始，测到末页后再补前面的页。
- 手动测速默认在 Windows 同时测 32 个节点，Android 同时测 24 个节点。在「设置 → 监测」开启「高速测速」后，下一轮手动批量测速按每个可用逻辑处理器 4 个位置计算，Windows 最多 64 个，Android 最多 48 个。节点多于并发数时会自动排队。
- Windows 在节点库右上角工具栏左侧显示已完成数和总数。按延迟排序时，测速期间保持当前排列，完成后更新排序。
- 两端更新了出厂配置中用于解析节点入口的 DNS，以改善按地区返回不同地址的订阅。Windows 切换网络后会重新检查测速内核，默认测速地址失败时会尝试备用地址。
- Windows 测速内核读取节点配置后随即移除该临时文件。
- Android 批量测速遇到一组请求失败时，进度会计入该组已处理的节点并继续测试后续节点。

Windows 可使用应用内更新或 x64 安装包。Android 可使用应用内更新，也可下载与设备架构匹配的 APK 或通用 APK。

## Air Proxy 1.1.5

- Manual tests on Windows and Android start in the order shown in the node library. As each slot becomes available, the next node starts. Selected nodes follow the same order. On Windows, testing begins on the current page and wraps after the last page.
- Manual tests run up to 32 nodes at once on Windows and 24 on Android by default. Turn on **High-speed testing** under **Settings → Monitoring** to use four slots per available logical processor for the next batch, up to 64 on Windows or 48 on Android. Additional nodes stay in the queue.
- The Windows node library shows the completed and total counts to the left of the toolbar. When sorted by latency, the list keeps its order until the test finishes.
- Updated the factory DNS settings for resolving node entry addresses when a subscription returns different answers by region. Windows rechecks the diagnostic core after network changes and tries an alternate URL when the default test request fails.
- Windows removes the temporary node configuration as soon as the diagnostic core has loaded it.
- Android now counts nodes from a failed batch request in its progress and continues with the next nodes.

Update in the app or use the Windows x64 installer. Android users can also install the APK for their architecture or the universal APK.
