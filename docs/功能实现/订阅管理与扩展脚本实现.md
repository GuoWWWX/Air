# 订阅导入、同步更新与扩展脚本实现

> 文档约定：命名规则、扩展脚本沙箱与二维码流转在「[1. 双端共用实现](#1-双端共用实现)」统一说明；两端迥异的网络下载、加密持久化及后台定时更新机制在「[2. 电脑版实现（Windows 桌面端）](#2-电脑版实现windows-桌面端)」与「[3. 手机版实现（Android 移动端）](#3-手机版实现android-移动端)」分开说明。

## 1. 双端共用实现

### 1.1 订阅命名识别与同名去重状态机
- **核心文件**：[subscription-name.ts](../../src/shared/proxy/subscription-name.ts)
- **实现机制**：
  - 导入优先级：`用户手填名称` > `响应头 Profile-Title`（自动识别普通文本与 `base64:` 前缀 UTF-8 编码）> `文件名称` / `URL 主机名`。
  - 维护 `autoName` 与 `baseName` 标记：用户未手改过名称时，远程同步到新的服务端标题可自动更新显示名；手动改名后锁定不再被覆盖；多条不同来源若返回相同基础标题，自动按序编号为 `Title (1)`、`Title (2)` 并持久化，刷新时保留编号。

### 1.2 订阅扩展规则与 QuickJS 脚本沙箱
- **核心文件**：[subscription-extension.ts](../../src/shared/proxy/subscription-extension.ts)、[SubscriptionTool.tsx](../../src/shared/ui/SubscriptionTool.tsx)
- **实现机制**：
  - 每份订阅支持独立保存两类扩展：JavaScript 转换脚本与附加分流规则文本。
  - **沙箱执行（`extendSubscription`）**：使用 `@jitl/quickjs-wasmfile-release-sync` 与 `quickjs-emscripten-core` 在独立 WASM 沙箱实例中解析订阅 YAML，执行用户提供的 `main(config)` 函数并受严格的运行时间与内存上限约束，返回对象后重新序列化为合法 YAML，再将附加规则前置插入该订阅 `rules` 列表头部。
  - 前端提供 [YamlEditor.tsx](../../src/features/subscriptions/YamlEditor.tsx)（桌面）和 [workflows.tsx](../../android/web/src/workflows.tsx) `YamlEditor`（手机），支持「生效配置 / 本地修改 / 订阅原文」多视图对照编辑及“恢复订阅原文”。

### 1.3 订阅列表排序与二维码导入/生成
- [useSubscriptionOrder.ts](../../src/shared/proxy/useSubscriptionOrder.ts)：统一封装订阅条目的上移/下移排序与本地持久化逻辑，与当前出站选择和浏览勾选范围解耦。
- 二维码扫描与分享：引入 `jsqr` 对相机视频帧或相册二维码图片解码提取 URL；引入 `qrcode` 在纯本机端把订阅链接渲染为二维码供其他设备扫码导入。

## 2. 电脑版实现（Windows 桌面端）

### 2.1 下载校验与独立安全存储（SQLite + DPAPI）
- **核心文件**：[subscriptions/mod.rs](../../src-tauri/src/subscriptions/mod.rs)、[storage/mod.rs](../../src-tauri/src/storage/mod.rs)、[storage/documents.rs](../../src-tauri/src/storage/documents.rs)
- **实现机制**：
  - **远程拉取**：使用 `reqwest` 下载 HTTP/HTTPS 订阅，解析 `Profile-Title`、`Content-Disposition`、`subscription-userinfo`（剩余/已用流量及到期时间）与 `profile-update-interval` 响应头，导入前使用诊断内核试校验解析出节点与分组预览。
  - **混合存储架构**：
    - `air.sqlite3` 保存订阅索引、URL、流量用量、自动更新偏好与节点测速记录。
    - 订阅正文 YAML（区分下载 `original` 原文与本地编辑 `local` 副本以及扩展示例渲染结果 `rendered`）由 `documents.rs` 使用 **Windows DPAPI** 加密为 `.airsub` 独立文件保存在 `subscriptions` 目录中，先落临时文件再 `sync_all` 原子替换并清理孤立文件；订阅 URL 同样经加密保存。

### 2.2 后台自动更新轮询与前端导入任务
- **后台更新（[subscription_updates.rs](../../src-tauri/src/storage/subscription_updates.rs)）**：应用进程存活期间（含窗口收起到托盘时）按订阅设定的更新间隔（默认取响应头有效小时数，未提供为 24 小时，支持 1~720 小时）检查到期任务并静默下载刷新；若该订阅存在 `local` 本地 YAML、节点覆写或扩展改动，则自动暂停自动更新并保留本地状态直至用户手动恢复。
- **前端界面与状态**：
  - [importTasks.ts](../../src/features/subscriptions/importTasks.ts) 与 [SubscriptionImport.tsx](../../src/features/subscriptions/SubscriptionImport.tsx)：管理多任务异步导入队列、摄像头权限与二维码图片解码。
  - [useSelectedSubscriptions.ts](../../src/features/subscriptions/useSelectedSubscriptions.ts) & [Subscriptions.tsx](../../src/features/subscriptions/Subscriptions.tsx)：保存订阅勾选筛选范围（多选来源后汇总展示该范围下的节点与分组）及删除订阅时的引用清理。

## 3. 手机版实现（Android 移动端）

### 3.1 原生 HTTPS 拉取与原子文件持久化
- **远程下载（[MainActivity.kt](../../android/app/src/main/java/app/air/android/MainActivity.kt) `fetchSubscription`）**：强制只接受 HTTPS 订阅 URL（无 `userInfo`），手工控制最多 5 跳 301/302/307/308 重定向并施加 `MAX_SUBSCRIPTION` 体积上限保护，返回正文与 `Profile-Title` / `subscription-userinfo` / `profile-update-interval` 元数据。
- **本地存储（[ConfigFiles.kt](../../android/app/src/main/java/app/air/android/ConfigFiles.kt)）**：
  - 放置在不受系统云备份影响的 `context.noBackupFilesDir/config/` 下；通过跨进程文件锁 `library.lock` + `AtomicFile` 读写主索引 `library.json`。
  - 每份订阅序列化后按 SHA-256 摘要内容寻址存储于 `subscriptions/<hash>.json` 中，写入成功后再回收废弃的旧哈希文件，崩溃时不破坏已有配置。
- **写串行队列（[app.tsx](../../android/web/src/app.tsx) `enqueueWrite`）**：所有修改订阅、规则或扩展示例的操作全部进入同一 Promise 链式队列，必要时重新执行 QuickJS `extendSubscription` 扩展编译与 `yamlProfile` 校验，再整体更新或仅通过 `saveOutbound` 快速保存模式与出站。

### 3.2 后台预下载调度与回到前台合并
- **核心文件**：[SubscriptionUpdateService.kt](../../android/app/src/main/java/app/air/android/SubscriptionUpdateService.kt)
- **实现机制**：
  - 仅在配置好非 `edited` 且开启 `autoUpdate` 的订阅时，利用 Android 系统 `JobScheduler` 注册网络条件下的周期预下载任务。
  - 后台只将新拉取的订阅响应暂存到暂存区，不直接在后台粗暴改写 `library.json`；用户切回应用前台或刷新列表时，前端通过 `stagedSubscription` 消费该预下载内容，经 `yamlProfile` 校验后经由 `enqueueWrite` 安全合并进订阅库。
