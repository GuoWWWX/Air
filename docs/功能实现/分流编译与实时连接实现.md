## 1. 双端共用实现

### 1.1 规则匹配总体顺序与兼容原则
双端在规则模式下使用以下匹配顺序。内核采用第一条命中规则的出口。

1. **全局规则**按保存顺序匹配。来自实时连接或连接日志的应用、域名和 IP 策略也保存在这里。同一应用的域名/IP 例外优先于该应用的整体规则。
2. **基础网络保障**先放行私有地址与私有域名。启用 QUIC 拦截时，在此处插入对应的 UDP 规则。
3. **当前出站的规则集**保留有效规则的顺序、支持的 `RULE-SET` 和对应的 `rule-providers`。没有可用的规则或订阅默认出口时，补入 `GEOSITE,cn,DIRECT` 与 `GEOIP,CN,DIRECT,no-resolve`。
4. **默认出口**由最后一条 `MATCH` 决定。默认沿用解析后规则集中的 `MATCH`，缺省时使用当前出站。用户在设置里指定的默认出口优先于规则集的 `MATCH`。

**绑定解析**从当前对象开始，遇到明确绑定就停止。节点先查自身，再查本次选中它的自定义分组，然后查所属订阅的绑定，最后取该订阅自带规则。从「全部节点」选择时只按节点和订阅解析。把节点收藏进多个分组不会改变这个结果。「不使用规则集」停止向上查找，继续应用全局规则、基础保障、国内直连与默认出口。

| 当前出站 | 跟随默认时的行为 |
| --- | --- |
| 订阅节点 | 跟随所属订阅。整份订阅可以借用另一订阅的规则，也可以绑定自建规则集。 |
| 自定义分组作为自动出站 | 优先采用分组绑定。同一订阅的成员默认跟随该订阅，混合来源的分组默认使用国内直连兜底。 |
| 自定义节点或新建多跳链路 | 默认使用国内直连兜底，可以单独绑定规则集。 |
| 升级前已保存的多跳链路 | 未设置绑定时继续跟随末跳节点所属订阅，保留旧链路的出站行为。 |

两端都在 `routing.ruleLibrary` 中保存可选的 `sets` 与 `bindings`。绑定用对象类型和稳定 ID 定位，名称仅用于显示。规则集引用可指向订阅或自建规则集，显式停用保存为 `none`，跟随默认则移除该对象的绑定记录。删除自建规则集时一并移除所有指向它的绑定，重新按上表解析。

「分流规则库」只读展示订阅规则，支持克隆模板和导入、编辑、导出标准 YAML。直接绑定订阅时，自动策略组保留来源中的策略、成员与顺序。克隆为独立模板时，策略组保留其类型、探测参数和成员顺序。原订阅的节点位置映射到当前出站，重复节点位置合并，直连与拒绝成员保留。要持续使用另一订阅的原始节点、自动组以及后续更新，可以直接绑定该订阅。

### 1.2 应用与域名/IP 精细分流策略归并（`connection-policy.ts`）
- **核心文件**：[connection-policy.ts](../../src/shared/proxy/connection-policy.ts)
- **实现机制**：
  - 点击实时连接或连接日志条目打开分流策略弹窗/抽屉时，`extractHostInfo` 自动剥离端口并区分 IP 地址或域名，并通过 `suggestRootDomain` 识别多级公共后缀（如 `.com.cn`、`.co.uk`、`.co.jp`）给出「仅完整域名 / 域名及根域名 / 目标 IP」推荐匹配项。
  - 用户针对同一应用既可设**整个应用默认出站**（保持订阅规则 / 直连 / 代理 / 指定节点/链路/分组 / 拒绝），也可只针对**当前或手填的特定域名/IP** 设置叠加复合规则（编译为 `AND,((PROCESS-NAME,app),(DOMAIN-SUFFIX,host)),target`）。
  - 保存时由共享逻辑确定性归并规则列表：
    - 始终保证**特定应用的「应用 + 域名/IP」细分复合规则排在该应用「整个应用」粗规则之前**，防止整包规则抢先截胡导致细分规则永远不生效；
    - 相同目标或同应用细分条目自动更新去重，支持自定义域名/IP 校验（`validatePolicyHostValue`）。

设置页通过共享的 `GlobalRuleList` 将 Windows 进程或 Android 包名对应的规则聚合到一行。独立域名和 IP 规则各占一行。聚合保留底层规则的匹配条件与顺序，包括进程路径限制。整组关闭后再次启用会恢复此前各条规则的启停状态。点击行可在桌面弹窗或手机底部面板维护整体出站和例外，亦可调整优先级。

### 1.3 连接出口路由展示与搜索口径
双端「实时连接」与「连接日志」统一对代理流量直接显示最终出口节点名称（不再附加冗余「代理 · 」文字前缀），直连与拒绝保留对应色调标签，点击详情即可查看完整命中规则、链路跳点并随时改写策略。

## 2. 电脑版实现（Windows 桌面端）

### 2.1 全局 YAML 配置与规则编译
- **配置文件管理（[routing/mod.rs](../../src-tauri/src/routing/mod.rs)、[routing/file.rs](../../src-tauri/src/routing/file.rs)、[ConfigFilePanel.tsx](../../src/features/settings/ConfigFilePanel.tsx)）**：全局配置保存在 `air-config.yaml`，读写带文件修订号冲突校验；每次经 UI 表单保存前自动把上次全文（保留用户手写注释）备份到同目录的 `air-config.previous.yaml`。
- **运行时规则物化（[config.rs](../../src-tauri/src/proxy/config.rs)、[subscription_rules.rs](../../src-tauri/src/proxy/subscription_rules.rs)）**：
  - 编译运行时 Mihomo 配置时，`RuleOutbounds` 仅按需物化分流规则引用到的跨订阅节点与嵌套代理组（以来源 ID + 名称哈希隔离别名 `air-group-*`），防止多订阅同名分组冲突并控制内存开销。
  - 节点、分组与链路统一按当前出站解析规则。SQLite 保存的启动目标可以携带分组上下文或链路 ID。设置页预览用同一配置编译入口及网络设置生成内核规则。旧版无选定出站的 YAML 仍可读取原有分流字段。

### 2.2 实时连接采集、Windows 进程/UWP 图标提取与策略断开
- **核心文件**：[proxy/mod.rs](../../src-tauri/src/proxy/mod.rs)、[windows_apps.rs](../../src-tauri/src/proxy/windows_apps.rs)、[package_logo.rs](../../src-tauri/src/proxy/windows_apps/package_logo.rs)、[Dashboard.tsx](../../src/features/home/Dashboard.tsx)、[ConnectionsPage.tsx](../../src/features/connections/ConnectionsPage.tsx)、[ConnectionPolicyDialog.tsx](../../src/features/connections/ConnectionPolicyDialog.tsx)
- **实现机制**：
  - 通过连接快照定时轮询内核 `/connections`（回环端口转换时结合 `GetExtendedTcpTable` 还原真实本地客户端进程）；使用进程可执行文件路径或 UWP `AppxManifest` 包清单解析友好应用名与 PNG Base64 图标（缓存上限 256 项）。
  - 在 `ConnectionPolicyDialog` 保存分流策略时按当前选定「进程名 / 完整进程路径」与细分域名编译并写入 `air-config.yaml`，立即热更新运行中内核规则，并按用户选择调用 `close_matching_connections` 断开该应用的现有连接使新策略即时生效；在 [RoutingSettings.tsx](../../src/features/settings/RoutingSettings.tsx) 中支持拖拽/按钮排序、启用开关及「预览生效规则」。

## 3. 手机版实现（Android 移动端）

### 3.1 前端运行时编译与绑定持久化

Android 将规则与绑定保存在 `library.json` 的 `routing` 段。`resolvedRuleSet()` 根据实际选中的节点、分组或链路解析绑定，`compile()` 将全局规则、基础保障、规则集和最后的 `MATCH` 写入传给原生内核的运行计划。设置页「预览生效规则」从同一编译结果读取规则，并注明解析后的来源。恢复默认全局规则时保留自建规则集及其绑定。[model.ts](../../android/web/src/model.ts) · [settings.tsx](../../android/web/src/settings.tsx)

### 3.2 实时速率计算、应用包信息提取与策略抽屉
- **核心文件**：[ConnectionSamples.kt](../../android/app/src/main/java/app/air/android/ConnectionSamples.kt)、[MainActivity.kt](../../android/app/src/main/java/app/air/android/MainActivity.kt)、[AirVpnService.kt](../../android/app/src/main/java/app/air/android/AirVpnService.kt)、[views.tsx](../../android/web/src/views.tsx)、[connection-policy.tsx](../../android/web/src/connection-policy.tsx)
- **实现机制**：
  - 内核连接快照在原生侧采样记录每条连接前后字节差值计算实时 `downRate` / `upRate`，同时 `ConnectionSamples`（最大保留 200 条、30 秒 TTL）为已关闭连接打上 `closed = true` 与 `closedAt` 供「连接日志」区分活跃/已结束与筛选回溯。
  - `MainActivity` 结合 `PackageManager` 与 `applications` `LruCache(128)` 缓存按应用包名提取可读应用名称与缩放图标推送给 WebView。
  - 点击首页「实时连接」卡片（[views.tsx](../../android/web/src/views.tsx) `Home`）或「连接日志」卡片（`Connections`）打开 `ConnectionPolicySheet` 底部抽屉：在 Android 10+（`sdk >= 29`）支持按应用包名（或按「应用包名 + 精细域名/IP」复合条件）及全系统范围配置直连/代理/指定出口，保存经 `validateRouting` 与 `validatePlan` 校验后实时 `apply` 并支持断开匹配旧连接。
