# 代理内核、系统接管与网络 DNS 实现

> 文档约定：概念与网络模型相同的部分在「[1. 双端共用实现](#1-双端共用实现)」统一说明；进程模型、系统代理、TUN 与原生桥接分别在「[2. 电脑版实现（Windows 桌面端）](#2-电脑版实现windows-桌面端)」与「[3. 手机版实现（Android 移动端）](#3-手机版实现android-移动端)」分开说明。

## 1. 双端共用实现

### 1.1 出站模式与基础配置抽象
- **三种出站模式**：均定义在 [modes.tsx](../../src/shared/proxy/modes.tsx) 与 [state.ts](../../src/shared/proxy/state.ts) —— `rule`（按分流规则）、`global`（全局代理，对应内核 `GLOBAL` 选择组所选出口）、`direct`（全部直连）。
- **DNS 分层结构**：两端共享相同的多角色 DNS 语义（默认设置见 [network.ts](../../src/shared/proxy/network.ts)）：
  - `nameserver`（主 DNS）、`defaultNameserver`（解析 DoH/DoT 域名本身的引导 DNS）、`directNameserver`（直连出站使用，可选开启遵循分流规则 `respectRules`）、`proxyServerNameserver`（解析节点服务器域名）、`fallback`（备用 DNS 与 `fallbackDomains` 分流触发条件）以及 `domainDns`（分域专有 DNS `nameserver-policy`）。
  - 支持 `redir-host`（真实 IP）与 `fake-ip`（虚假 IP 映射及排除域 `fakeIpFilter`）两种增强模式，以及 DNS 缓存算法选择与本机 `localHosts` / 订阅 `hosts` 注入。
- **内嵌地理规则库（GeoData）**：两端构建产物均内嵌锁定版本的 `GeoIP` / `GeoSite`（版本由 [mihomo-data.json](../../scripts/mihomo-data.json) 统一管理），冷启动时写入内核工作目录，保证离线或首次安装即可匹配国内/私有规则。
- **经代理检测公网出口**：代理运行期间通过真实代理通道探测出口公网 IP、国家码、城市与运营商归属信息；切换节点后重新检测，未变化或同会话返回页面时复用缓存。

## 2. 电脑版实现（Windows 桌面端）

### 2.1 内核生命周期与单节点热切换
- **独立子进程模式（[mihomo/mod.rs](../../src-tauri/src/mihomo/mod.rs)、[runtime_kernel.rs](../../src-tauri/src/proxy/runtime_kernel.rs)）**：
  - 使用随包或用户指定的 `mihomo` 可执行文件在独立临时工作目录启动，分配随机监听端口与控制密钥，并用 Windows Job Object 绑定子进程确保主进程异常退出时子进程一同结束。
  - 首选固定本地混合端口 `7890`（`loopback.rs` 探测冲突后动态分配）。
  - 每次启动写入嵌入式 GeoData（[geodata.rs](../../src-tauri/src/mihomo/geodata.rs)）并动态编译配置 YAML。
- **配置热重载与无重载切节点（[config.rs](../../src-tauri/src/proxy/config.rs) `prepare_node_switch`）**：切换单节点时若新旧配置除 `proxies` / `GLOBAL` 成员外其余字段完全一致、且待切换节点已预载在缓存槽位（最多保留最近 8 个节点）内，则直接调用控制接口 `select_global` 并关闭旧连接，不重启内核；否则下发配置全量重载。

### 2.2 系统代理接管与恢复
**WinINet 注册表接管（[windows.rs](../../src-tauri/src/proxy/windows.rs)）**：

- 通过 `InternetSetOptionW` 配置当前用户系统代理（地址 `127.0.0.1:port` 与绕过列表）。
- 开启前先将用户原有的系统代理状态持久化到恢复日志 `system-proxy-restore.json`；停止代理、程序退出或下次启动异常恢复时，按日志精确还原原始系统代理，避免系统断网。

### 2.3 Windows 虚拟网卡服务（免每次 UAC 提权）
**双通道会话（[tun_service/](../../src-tauri/src/proxy/tun_service/)、[TunServiceButton.tsx](../../src/features/proxy/TunServiceButton.tsx)）**：

- 未安装服务时点击「安装服务」请求一次管理员授权注册 Windows 系统服务 `air-tun-service`。
- 日常在托盘、仪表盘或设置中开关虚拟网卡时，由主程序通过命名管道 IPC 通知特权服务托管运行 `mihomo` 与 Wintun 驱动；关闭虚拟网卡时安全停止服务会话并切回本地用户进程或停机。

### 2.4 TUN 下局域网设备发现守护路由
**多播旁路路由（[lan_discovery.rs](../../src-tauri/src/proxy/lan_discovery.rs)）**：

- Wintun 虚拟网卡开启时会以高优先级接收流量，导致局域网投屏/打印机发现（mDNS `224.0.0.251`/`ff02::fb`、SSDP `239.255.255.250`/`ff02::c`、LLMNR `224.0.0.252`/`ff02::1:3`）被错误劫持。
- 开启 TUN 后后台监控网络接口变化，为这些多播地址在当前物理网卡上维护带有 45 秒有限租期（`LEASE_SECONDS = 45`）的临时转发路由表项，网络切换时刷新、关闭 TUN 时立即清除。

### 2.5 桌面设置与 DNS 测试
- **实现文件**：[network.rs](../../src-tauri/src/network.rs)、[NetworkPanel.tsx](../../src/features/settings/NetworkPanel.tsx)
- 在后端校验各组 DNS URI 协议头与格式，支持「从当前订阅导入 DNS 地址」与「测试解析指定域名」返回耗时和解析结果。

## 3. 手机版实现（Android 移动端）

### 3.1 JNI 内嵌内核与串行控制（`Core.kt`）
- **核心文件**：[Core.kt](../../android/app/src/main/java/app/air/android/Core.kt)
- **实现机制**：
  - 不使用独立子进程，而是直接加载 APK 内的 `libmihomo` 原生库（`io.github.oviron.libmihomo.Clash`）。
  - 所有内核配置加载与启停由单线程执行器 `Core.worker` 串行执行；通过 `prepare` 提前初始化并在 `stoppedProfile` 缓存上次配置。
  - **运行中无感切换出站与模式（`applyLive`）**：先比对 `sameConfig(previous, next)`（包括有效 `hosts` 与策略组键集合），若结构一致则仅调用 `changeProxy` 与 `updateConfig(mode)` 实时更新并分别调用 `closeAllConnections`（切模式）或 `closeProxiedConnections`（仅清理非 `DIRECT` 代理连接），无需重启 VPN 隧道。

### 3.2 Android 系统 VPN 前台服务（`AirVpnService.kt`）
- **核心文件**：[AirVpnService.kt](../../android/app/src/main/java/app/air/android/AirVpnService.kt)
- **实现机制**：
  - 首次启动在 [MainActivity.kt](../../android/app/src/main/java/app/air/android/MainActivity.kt) 调用 `VpnService.prepare` 申请系统 VPN 授权，授权后启动 `AirVpnService` 前台服务。
  - 按 `tunnel` 参数建立 TUN 接口：设置 MTU、可选 IPv4/IPv6 地址与默认路由、可选绕过网段 `excludeRoutes`（Android 13+ / SDK 33 起用 `Builder.excludeRoute`）、默认排除 Air 自身包名防回环（`addDisallowedApplication`），并将获取的 `tunFd` 移交给 `libmihomo` 接管流量（支持内部 DNS 53 端口劫持）。
  - 前台常驻通知定时读取 `Core.traffic()` / `Core.totals()` 刷新通知栏实时网速，连接异常或撤销系统授权时主动收尾并更新状态快照供 WebView 轮询/推送同步。

### 3.3 移动端网络编译、DNS 探测与本地回退
- **核心文件**：[configuration.ts](../../android/web/src/configuration.ts)、[network-settings.tsx](../../android/web/src/network-settings.tsx)、[DnsProbe.kt](../../android/app/src/main/java/app/air/android/DnsProbe.kt)
- **实现机制**：
  - 网络、TUN、接入端口与绕过网段由 TypeScript 在 [configuration.ts](../../android/web/src/configuration.ts) 与 `model.ts` 中直接编译为标准 `plan.config` JSON；在提交保存前经 `AirDiagnostics` 调用原生 `validatePlan`（即 `Core.validate` -> `validateConfig`）确认内核可正常载入。
  - 手机端留空混合端口即可关闭本地 HTTP/SOCKS 监听；DNS 测试请求经桥接发往 `:diagnostics` 进程里的 `DnsProbe.kt` 返回延迟毫秒与解析 IP 列表。
