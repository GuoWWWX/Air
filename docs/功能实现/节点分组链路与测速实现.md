# 节点库、分组、多跳链路与测速监测实现

## 1. 双端共用实现

### 1.1 节点视图与本地覆写
- 支持**卡片**（三档布局密度：`紧凑` / `标准` / `详细`）和**列表/表格**视图切换，筛选条件、卡片密度与多选状态保存在 UI 偏好中（[NodeLibrary.tsx](../../src/features/nodes/NodeLibrary.tsx)、[views.tsx](../../android/web/src/views.tsx) `Nodes`）。
- 订阅节点支持保存**本地节点覆写**（修改显示名称、服务器地址、端口等而不篡改下载原文），并可随时一键恢复订阅原值。
- 支持添加**自定义节点**（HTTP / HTTPS / SOCKS5 等，含认证凭据），在独立表单内直接验证与测速。

### 1.2 订阅 `hosts` 作用域隔离与多跳链路编译
- **顶层 `hosts` 按作用域注入**：当订阅自带顶层 `hosts`（包括同一域名的多条 IPv4/IPv6 地址）时，两端均会按节点所属订阅分组生成独立 `hostScopes`，测速与正式连接只激活当前所测/所用节点关联来源的 `hosts` 映射，避免不同订阅同名域名解析互相污染。
- **多跳链路（`dialer-proxy`）**：至少 2 个可用节点可按顺序组成链路（前置 → 中转 → 出口），两端均将每一跳编译为带 `dialer-proxy` 指向上一跳内部名称的代理条目，末跳作为真实出口参与连接与整链测速。

### 1.3 节点延迟统计口径
每个节点保留 24 小时测速样本队列，计算最近可用延迟、24 小时可用率（成功次数 / 总样本数）及平均延迟；按钮样式统一复用 [NodeLatencyButton.tsx](../../src/shared/ui/NodeLatencyButton.tsx)。

## 2. 电脑版实现（Windows 桌面端）

### 2.1 基于 Rust `Scheduler` 的并发探测与同节点去重
- **核心文件**：[monitoring/mod.rs](../../src-tauri/src/monitoring/mod.rs)、[mihomo/mod.rs](../../src-tauri/src/mihomo/mod.rs)、[useNodes.ts](../../src/features/nodes/useNodes.ts)
- **实现机制**：
  - 测速采用独立诊断 `Kernel` 实例（不干扰主代理会话，主代理停止时同样可测）。
  - `Scheduler` 基于 Tokio `Semaphore` 控制并发上限：**前台人工测速并发上限 `32`**，**后台自动监测并发上限 `8`**，单次探测超时 **`8` 秒**（`PROBE_TIMEOUT`），默认后台间隔 **`300` 秒**。
  - 同一节点正在探测时，重复请求通过 `pending` 表中的 `Shared<BoxFuture>` 合并复用同一个探测结果，避免重复占用带宽与内核端口。
  - 前端 `useNodes.ts` 中 `measure(id)` 通过 `inFlight` Set 按节点 ID 独立发起测速与刷新（支持同时点测多个不同节点）；批量测速 `batch(ids)` 启动后前端通过 `poll()` 增量拉取 `completedIds` 并调用 `refreshMetrics` 局部刷新节点卡片数据；`cancelBatch()` 可随时中止批量任务。

### 2.2 树形来源与自定义多级分组、独立链路面板
- **自定义分组（[custom_groups.rs](../../src-tauri/src/custom_groups.rs)、[CustomGroupDialog.tsx](../../src/features/nodes/CustomGroupDialog.tsx)、[NodeSourceTree.tsx](../../src/features/nodes/NodeSourceTree.tsx)）**：持久化保存于 `custom-groups.json`，通过 `parentId` 支持多级子分组嵌套、重命名、批量勾选加减成员及整组右键管理；订阅分组亦可在详情内编辑名称、策略与成员。
- **链路（[chains/mod.rs](../../src-tauri/src/chains/mod.rs)、[ChainInspector.tsx](../../src/features/chains/ChainInspector.tsx)）**：在独立链路面板编排跳序、命名保存与逐跳测试验证。

## 3. 手机版实现（Android 移动端）

### 3.1 跨进程诊断与动态补位测速（`ProbeTiming.kt` & `AirDiagnostics.kt`）
- **核心文件**：[ProbeTiming.kt](../../android/app/src/main/java/app/air/android/ProbeTiming.kt)、[Core.kt](../../android/app/src/main/java/app/air/android/Core.kt)、[AirDiagnostics.kt](../../android/app/src/main/java/app/air/android/AirDiagnostics.kt)、[MainActivity.kt](../../android/app/src/main/java/app/air/android/MainActivity.kt)
- **实现机制**：
  - 测速任务经 `MainActivity` 独立单线程执行器 `probeRequests`（不阻塞主 `requests` 线程上的保存/切换操作），通过 `ContentProvider` 跨进程委派给 `:diagnostics` 进程里的 `Core.probe` 执行（使用取消代次 `probeGeneration` 实现瞬时 `cancelProbe`）。
  - **`measureDelays` 调度**：最多保持 **`PROBE_CONCURRENCY = 24`** 个并发测速槽位，任一节点完成或超时立即补充下一个排队节点，不被个别慢节点卡住整批队列；默认总超时 `4500ms`，主探测地址 `1500ms` 未返回时自动并发发起备用地址探测（默认 Google 204 与 Cloudflare 204 互为备选）。
  - **单节点结果即时流式回传**：`measureDelays` 每完成一个节点即回调 `onResult(alias, delay)`，由 `AirDiagnostics` 经 Android `Messenger` `Bundle` 无节流即时推回 `MainActivity`，经 `bridge.ts`（`onProgress(completed, alias, delay)`）立即送达前端，彻底避免等到整批结束才更新界面。

### 3.2 多节点单点排队并发、即时解锁与行内进度标
- **核心文件**：[app.tsx](../../android/web/src/app.tsx)（`drainProbeQueue` / `enqueueManualProbe` / `cancelProbe`）、[views.tsx](../../android/web/src/views.tsx)
- **实现机制**：
  - 节点卡片的 `<NodeLatencyButton>` 不再被批量测速整体禁用（仅 `disabled={busy}`），所有当前未处于测速中的卡片随时可点击。
  - 前端维护三层优先级队列：
    1. **草稿/整链即时测试（最高优先）**：编辑器内「测试连接」与「测整链」；
    2. **用户手动点选队列（中优先）**：连续点选多个节点时立即全部呈现转圈态，经 `80ms` 短合并窗口（`MANUAL_PROBE_COALESCE_MS`）或随当前批次结束后一次性打包发往 `Core.probe` 并发测速（单次上限 `72` 个，跨 `hostScopes` 自动分片）；
    3. **批量测速分片（低优先）**：按下工具栏闪电或选中批量测速时按分片执行，分片间隙优先响应用户手动点选的节点。
  - **即时解锁**：任意单节点结果一经流式回传，前端立即写入样本更新延迟显示并从 `activeManualIdsRef`/`activeBatchIdsRef` 移除该节点 ID，卡片即刻停止转圈解锁为可再点状态；批量测速总进度（`done/total`）以紧凑蓝色 `Tag` 显示在节点工具栏同一行右侧（点击旁边旋转按钮即可随时停止）。

### 3.3 移动端分组筛选（含自动组）与 `AirMonitorService`
- **分组（[model.ts](../../android/web/src/model.ts)、[workflows.tsx](../../android/web/src/workflows.tsx) `GroupEditor`）**：支持手动选节点建组与按「订阅来源 + 最大延迟阈值 + 节点数量上限」动态计算成员的自动分组；顶部作用域选择器支持在「全部 / 订阅 / 分组」间树形切换。
- **后台监测（[AirMonitorService.kt](../../android/app/src/main/java/app/air/android/AirMonitorService.kt)）**：通过 Android `JobScheduler` 按设定的间隔（至少 15 分钟）调度 `:monitor` 进程运行内置 `Core.probe` 对 `monitorPlan` 执行后台定时测速并将样本合并回主库。
