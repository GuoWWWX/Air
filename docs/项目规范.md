# Air 项目规范

本规范记录 Air 的产品目标与验收口径，包含规划中的功能。Windows 桌面版是功能基线，Android 按手机的系统权限与交互实现对应能力。端到端验收覆盖多个来源、代理节点及完整链路。各平台当前的实现与源码入口见 [目录与架构](目录与跨平台架构.md)。

桌面与手机版的页面导航和操作入口见 [页面功能说明](页面功能说明.md)。

## 首版范围

| 功能 | 行为 |
| --- | --- |
| 首页 | 程序默认打开首页。展示代理运行状态、已验证的实际出口 IP、当前链路、运行时长、实时上传下载和累计流量。首页还显示本地代理地址、当前线路所属订阅、服务状态、内存、实时连接和分组摘要。 |
| 代理控制 | 顶部右侧显示内核状态与「启动代理」或「停止代理」。同一栏提供规则、全局和直连三种出站模式，以及独立的系统代理和 TUN 开关。关闭系统代理或停止代理时恢复本应用修改的 Windows 代理设置。停止代理时解除本应用启用的 TUN 路由。TUN 需要管理员授权或已安装的 Windows 服务。 |
| 订阅管理 | 支持 URL、本地 YAML 文件和二维码导入。来源可单选或多选，按勾选范围展示分组和节点。支持编辑、删除来源及其条目，按来源保留本地覆写。 |
| 节点库 | 单页工作区。节点列表上方展示分组。页头右上角提供搜索、批量测速和「链路」入口。点击「链路」打开同页右栏。关闭编辑栏后节点列表恢复全宽，保留筛选、勾选和分页。默认卡片视图，可切换列表。两种视图共享筛选、排序、勾选和测速。 |
| 分组 | 订阅分组和自建分组共用列表、成员视图、策略和选择器。自建组可手动维护成员，或按订阅、地区、协议和监测门槛自动入组。成员变化和组内选路分别配置。 |
| 自定义节点 | 点击「添加自定义节点」，在节点库右栏录入 HTTP、HTTPS、SOCKS5 代理的名称、地址、端口和认证。可测试连接，再保存到节点库。自定义节点与订阅节点均可加入分组或用于链路的任意一跳。删除时检查组与链路引用。 |
| 链路 | 从页头「链路」进入同页右栏。右栏内可按名称搜索并选择已保存链路、新建链路或删除当前链路。首跳为前置，末跳为出口。显示各跳实际节点和验证后的出口 IP。链路故障时阻断已绑定的流量并提示失败阶段。 |
| 实时连接与诊断 | 显示应用、目标、命中规则、各跳实际节点、失败阶段和验证后的出口 IP。 |
| 测速 | 支持单跳和整链延迟、连通率与限量下载测速。比较某一跳的候选时固定其他跳及测试目标，逐个探测候选。 |
| 高级配置 | 支持编辑本地 `.yaml` 和 `.yml`，显示行号与语法高亮，并预览生效配置。订阅管理页也可按来源打开 YAML 编辑器。检测字段冲突、缺失引用和循环依赖，校验成功后才切换生效配置。 |
| 设置 | 设置首页按类别展示主题、语言与语言包和高级配置。点击整行进入对应子页，子页左上角可返回设置首页。主题支持跟随 Windows、浅色和深色，内置简体中文和英文，并支持导入本地 JSON 语言包。 |

## 订阅导入与内容管理

- 预览时拉取 URL 或二维码识别出的订阅链接，或解析本地 YAML 文件。确认后保存为订阅来源。导入失败时保留当前来源列表。二维码支持摄像头扫描和图片识别。
- 勾选来源决定当前内容视图的范围。节点和分组以来源和稳定 ID 标识，名称可重复。每个来源可编辑名称和远程链接。改链接时先验证新配置，再检查既有引用。
- 编辑订阅分组或节点会保存本地覆写。删除条目会添加可恢复的本地排除记录，按来源和条目 ID 保存，订阅刷新后继续生效。节点库和订阅页共用同一份结果。
- 删除整个订阅时，确认后自动解除指向该来源的规则集绑定，受影响的默认出口回到当前选中代理。全局规则若明确指向已删除的节点或分组，其匹配流量改为「拒绝连接」。Android 在规则或全局模式下删除最后一个可用出站时停止代理。单独删除分组或节点仍需按条目检查引用。

## YAML 文件编辑

- **订阅管理**的「编辑 YAML」可查看只读订阅原文、编辑本地副本和预览生效配置。初次编辑从原文创建副本。导入本地文件时在应用内编辑副本，也可导出编辑后的 YAML 文件。
- **自动校验**在内容修改后触发，先校验 YAML 语法，再检查内核配置与引用。错误提示给出行列或字段路径，定位到对应位置。「保存并应用」只在当前内容通过校验后生效。校验失败时保留编辑内容和上一份有效运行配置。
- **刷新与副本**独立保存。远程刷新更新订阅原文。启用本地 YAML 副本时，该副本仍为该来源的生效输入，用户可在编辑器切回订阅原文。结构化的单节点覆写仍按现有规则保留。
- **编辑器**保留原文缩进和注释，分别高亮键名、字符串、数字、布尔值与注释。订阅原文和生效配置使用同样的高亮规则。

## 分组的来源与策略

- **订阅分组**未覆写的成员与策略随订阅刷新。保留机场定义的代理组、类型、嵌套关系、代理集合和规则引用。同名组以订阅来源区分。组名、成员和选路策略支持独立的本地覆写，并可恢复订阅值。需要混合多个来源时可复制为自建组。
- **自建分组**可跨订阅添加节点，也可加入自定义节点。打开手动组后，勾选节点并点击右栏「加入选中节点」。也可以先勾选，再从批量操作「加入分组」选择目标手动组。自动入组的「候选来源」可以多选整份订阅或其中的原分组，按规则刷新成员。节点和监测记录按稳定 ID 去重。
- **组内选路**支持手动选择、自动选择与故障转移。手动选择用指定成员，自动选择按健康探测优先使用低延迟成员并应用切换容差，故障转移按组内顺序选择可用成员。订阅自带的其他内核策略可沿用，界面显示其实际策略。入组条件与组内选路分别设置。[Mihomo 自动选择](https://wiki.metacubex.one/en/config/proxy-groups/url-test/) · [Mihomo 故障转移](https://wiki.metacubex.one/en/config/proxy-groups/fallback/)
- 订阅规则可继续引用 `DIRECT` 和 `REJECT`。用于链路时校验是否能解析为实际代理，显示不兼容的成员、缺失引用或循环，阻断无法成立的链路。
- **编辑节点**从卡片或列表行的「⋯」打开右栏。自定义节点直接编辑保存。订阅节点的显示名称和连接参数按协议校验，修改保存为独立的本地覆写。刷新订阅时保留有效覆写，未覆写字段随订阅更新。「恢复订阅值」清除覆写后重新校验配置。

[Mihomo 代理组配置](https://wiki.metacubex.one/config/proxy-groups/) · [代理集合配置](https://wiki.metacubex.one/config/proxy-providers/)

## 链路与每跳选择

- 每一跳从同一个选择器选固定节点或引用一个分组。选择器可搜索订阅节点、自定义节点、订阅分组和自建分组。多选候选时可创建分组供该跳使用。通过「添加一跳」增加一个实际经过的代理阶段。
- 前置和最终出口都支持节点或分组，按链路顺序连接。组策略切换作用于后续新连接。末跳实际节点变更后，界面将出口 IP 标为待验证。
- 固定节点失效、手选成员失去资格或分组无可用成员时，显示失败的跳数和原因并阻断对应链路。失去资格的成员退出自动选路候选。

## 链路的保存与启动

1. 在节点库点击右上角「链路」。打开右栏后可选择已有链路或点击「新建」，在其中命名、选前置和出口、按需添加一跳和绑定 Windows 应用。已有家宽代理通过同页的「添加自定义节点」录入。配置时可以从仍可见的节点列表选择候选。
2. 「保存链路」校验引用、顺序、协议兼容性和应用规则冲突。保存成功后，右栏的链路选择器立即增加或更新该条，允许未绑定应用的链路先保存备用。不同应用可分别命中各自绑定的链路。同一个应用重复绑定时提示冲突。内核未运行时显示「待启动」。内核运行时，校验成功的修改应用到后续新连接，失败时保留上一份有效配置。
3. 顶部选「规则」并点击「启动代理」，由应用加载已保存的有效配置。按应用分流的验收路径还需开启「虚拟网卡」，让应用流量进入内核。系统代理和虚拟网卡由各自的开关控制。
4. 链路运行后可发起出口验证，并在「连接日志」核对指定进程的命中规则、实际前置和出口 IP。链路在同一个全局启停入口控制。
5. 从右栏删除当前链路时，先确认链路名称及受影响的应用。确认后同步移除链路和相关应用绑定，应用的新连接按剩余规则处理。运行配置校验失败时保留原链路和绑定。

## 监测、入组和排序口径

- **单跳**测「节点 → 测试站」，**整链**沿配置的代理顺序访问同一测试站。结果独立记录。整链历史关联每跳的实际节点、链路配置版本和探测目标，配置或探测目标变更后从新观测开始。
- **连续可用**以当前连续成功观测的首、末样本时间差计算。失败样本会中断连续记录。超过两个探测周期没有新样本，界面显示「监测暂停」并停止计时，恢复后从第一次成功重新计算。节点真实运行时长需要服务端数据。
- **可用率**为成功数除以有效探测数。睡眠、停测等无结果时段计入监测覆盖率的缺口，并在界面标明未知。没有足够样本时显示「样本不足」，延迟和可用率的未知项排在已知值之后。
- **最近延迟**显示最近一次同口径探测的耗时。探测失败时显示超时或实际失败状态。**平均延迟**为最近 24 小时内同口径成功探测耗时的算术平均，单位为毫秒。没有成功样本时显示「—」。整链和单跳的样本分别计算。
- **单节点测速**放在节点卡片或列表行的最右侧。点击最近延迟，或点击未测节点的「测速」，只探测该节点并更新它的最近延迟和平均延迟。探测中显示进度并合并重复请求，失败后可重试。
- **搜索节点**默认只显示页头右上角的搜索图标。点击展开短输入框并聚焦，按节点名称、来源或协议筛选，可收起输入框。
- **批量勾选与分页**在节点列表上方提供「本页全选」，部分选中时显示半选。它只勾选或取消当前筛选结果的当前页，其他页勾选按节点 ID 保留。页脚默认每页 6 条，可选 6、12、24、48 或 96 条，并显示页码和前后翻页。改每页条数时回第一页并保留筛选与勾选。
- **自动组默认值**为每 5 分钟探测一次、最近 24 小时可用率至少 98%、监测覆盖率至少 80%、有效样本至少 24 次、连续可用至少 30 分钟，最多保留 6 个。组内可调整门槛、窗口和上限，显示成员失去资格的原因。
- **排序**支持可用率、连续可用时长、最近延迟、平均延迟、延迟 P50 / P95、下载速度、最近探测时间、节点名称和订阅来源。列头可切换升降序。多列排序使用用户设置的次序，同值按订阅和节点 ID 保持顺序稳定。下载测速按需触发，后台监测使用轻量请求、限并发，并合并相同的探测任务。
- **订阅刷新**在订阅管理页发起，并显示各订阅的刷新结果。使用订阅原文时，成功后同步更新节点库与原组成员，沿用已有筛选、排序和仍有效的勾选及监测记录。启用 YAML 副本的来源按副本生效。单个订阅失败时继续使用它的上一份有效内容。节点库页头的「批量测速」发起主动探测。
- **验收赔钱机场**时先选一条在当前订阅中存在的节点。依次验证节点单跳、家宽代理和完整链路，通过独立请求核对实际出口 IP。AnyTLS 可以承载 TCP 前置，当前节点和家宽端口的可达性由实测确定。

## 外观、布局和语言包

- 主题偏好提供跟随 Windows、浅色和深色。主题颜色统一使用 CSS 变量，切换时立即生效并记住用户选择。
- 顶部控制栏、侧栏和页内操作栏保持可见。页面工作区占满可用高度，节点卡片、列表和详情按可用宽度适配。内容超出时在工作区滚动，页脚保持在工作区底部。
- 设置首页与子页在工作区居中，内容宽度最多 620 px，窄窗口随可用宽度收缩。分组面板随内容自然增高。设置的子页返回按钮回到设置首页，并恢复入口列表的滚动位置与键盘焦点。
- 节点库的浅色、深色、中英文及各编辑状态共用同一页头、分组区和节点工具栏。浅色工作区背景使用 `#F1F3F6`，节点卡片、顶栏、侧栏和编辑抽屉用白色，选中态和表头用浅蓝。卡片与列表只切换节点的展示形式。新建、编辑、选择和预览使用同一右栏，主区随右栏开关调整可用宽度。
- 内置语言为 `zh-CN` 和 `en`。从设置选择已有语言或「跟随系统」后立即更新界面并保存偏好，保留当前页面和代理会话。
- 启动时扫描 `config/languages/` 目录，两端均支持从设置导入 JSON。Windows 优先使用安装目录下的配置，Android 使用应用私有配置目录。订阅正文独立存放在同级的 `subscriptions/`。新增的有效文件在下次启动后可选。缺少的翻译回退至英文，订阅名和节点名保留原文。日期、数值按当前界面语言格式化。

语言包使用 UTF-8 JSON，文件名与 `code` 一致。[语言包示例及完整匹配规则](开发构建与清理.md#界面语言和自定义语言包)

## 技术栈

| 层 | 选型和职责 |
| --- | --- |
| 桌面 | Tauri 2 与 Windows WebView2。Rust 管理桌面生命周期、托盘和 IPC。首版用 Windows 11 做安装与 TUN 验收。 |
| 界面 | React、shadcn/ui（`@base-ui/react`）、Tailwind CSS v4、Motion、Lucide 图标、TypeScript、Vite、pnpm。React 保存界面状态与筛选条件，Rust 端提供实际运行状态和监测数据。 |
| 本地后端 | Rust、Tokio、reqwest、rusqlite。Rust 负责任务调度、测速、订阅下载、稳定性计算、配置校验和保存。 |
| 代理内核 | 独立运行 Mihomo。通过本机受保护的控制接口加载配置、选择节点和读取连接状态。跨订阅节点和分组使用稳定的内部标识。链路按顺序生成各跳的运行配置，后续跳的代理成员用 `dialer-proxy` 引用上一跳。分组套用在该跳的成员上，三种选路策略对应 `select`、`url-test` 和 `fallback`。空组使用 `empty-fallback: REJECT`。 |
| 数据与凭据 | 两端从 `config/subscriptions` 读取订阅正文。Windows 用 SQLite 保存索引和探测记录，订阅正文与 URL 经用户级 DPAPI 保护。Android 使用应用私有的 `noBackupFilesDir`，配置与临时运行文件分开存放。 |
| 原型 | Pen 的可编辑 `.pen` 文件。界面数据使用示例节点和示例出口。 |

技术参考见 [Tauri 2 运行权限](https://v2.tauri.app/security/runtime-authority/) · [shadcn/ui](https://ui.shadcn.com/docs) · [Base UI](https://base-ui.com/react/overview/quick-start) · [Mihomo 控制接口](https://wiki.metacubex.one/en/api/) · [Mihomo 链式代理](https://wiki.metacubex.one/config/proxies/dialer-proxy/) · [Windows 数据保护 API](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

## 开发和验收规范

1. **依赖方向** → verify: React 功能模块经类型化 IPC 调用 Rust。IPC 命令校验参数并调用功能模块。系统代理、数据库和内核访问由对应适配层实现。跨模块传稳定 ID，显示名可编辑。
2. **配置一致性** → verify: 两个机场的同名原组独立可选，卡片与列表切换后筛选、排序和勾选一致。嵌套组和代理集合展开后去重，刷新只重算自动组候选，手动组的失效节点有明确状态。错误 YAML、缺失节点或循环引用被拦截，正在使用的有效配置可继续运行。
3. **可复现的监测逻辑** → verify: 使用固定时钟和样本覆盖失败、睡眠后恢复、样本不足、入组上限、同值排序，以及修改家宽后重新计时。测试结果可区分单跳和整链。
4. **真实链路与系统回归** → verify: 验证订阅节点与自定义节点均可作前置或出口，分别绑定订阅分组与自建分组，检查手选、延迟切换和故障转移。验证多跳顺序、各跳实际节点与末跳出口 IP。刷新订阅后确认本地策略仍生效。验证无可用成员时阻断流量、顶部全局启停、TUN 权限失败及退出时恢复 Windows 代理设置。
5. **工程检查** → verify: 提交锁文件，TypeScript 使用严格模式。实现后以 `tsc --noEmit`、`cargo fmt --check`、`cargo clippy`、前端单测与 `cargo test` 检查。日志与测试数据检查脱敏，Mihomo 版本及校验和随发布配置记录。
6. **设置、语言和窗口布局** → verify: 从设置首页进入主题、语言或高级配置，再返回对应入口。宽窗口下设置内容不超过 620 px，窄窗口可收缩和滚动。中英文分别检查浅色和深色。导入自定义语言包，确认缺失文案回退、错误包有提示，重启后保留主题和语言。
7. **节点库操作** → verify: 从页头「链路」打开右栏，新建并保存两条链路，从选择器逐条打开和编辑。删除一条链路时核对受影响的应用，确认选择器和应用绑定同步更新。关闭右栏后恢复全宽，并保留节点筛选、勾选和分页。验证未绑定链路可保存、应用重复绑定提示冲突、卡片与列表切换和单节点测速。
8. **首页仪表盘** → verify: 打开应用进入首页。启动、停止和切换线路后，状态、计时和流量与内核一致。出口 IP 来自实际探测，切换线路后标为待验证。订阅未提供流量或到期信息时显示「未提供」。实时连接和前置组摘要可以打开对应页面。
9. **订阅管理** → verify: 分别通过 URL、文件、扫码和二维码图片导入。单选、跨来源多选和清空后核对分组与节点范围。分别编辑、排除并恢复一个订阅分组和一个节点，刷新后检查覆写仍生效。删除被引用的订阅后，检查受影响的规则集绑定已解除、默认出口已回落，明确指向已删除节点或分组的全局规则拒绝匹配流量，其余订阅的规则仍可用。
